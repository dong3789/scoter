# Scoter 기획서

작업명 Scoter. 영양제 스택 커뮤니티.

작성일: 2026-09-29

이 문서는 만드는 범위를 고정한다. 점수 앱, 식단 앱, 판매 채널은 여기 없다.

## 1. 한 줄

지금 먹는 영양제 제품을 체크하면 스택 카드가 공개되고, 같은 제품을 체크한 사람이 바로 보인다.

## 2. 목표

영양제 커뮤니티를 만드는 것이다.

함량 합계와 군 평균은 그 카드가 쌓인 뒤에 따라온다. 첫 성공은 "내 제품을 체크했더니 같은 제품을 먹는 사람의 스택이 보인다"이다.

## 3. 쓰는 사람

영양제를 이미 먹고, 다른 사람은 어떤 제품을 체크했는지 보고 싶은 사람. 첫 사용자는 기획자 본인이다. 본인 스택이 첫 카드다.

## 4. 이미 정해진 것

- 영양제만 다룬다. 음식, 검진, 웨어러블, 구매, 약사 상담은 넣지 않는다.
- 모이는 단위는 글이 아니라 스택 카드다. 제품, 1회 분량 배수, 먹는 시간.
- 카드에 짧은 질문을 달 수 있다.
- 커뮤니티가 생기는 방의 단위는 제품이다.
- 제품 목록은 식약처 건강기능식품 영양성분 데이터로 채운다. 없는 제품은 직접 추가한다.
- 한 달에 한 번 품목제조신고번호로 다시 받는다. 사람이 고친 함량은 그 갱신이 덮어쓰지 않는다.
- 고민 카테고리는 처음에 고르지 않는다. 성분이 3개 이상 겹치는 사람들이 첫 군이다. 수면, 운동 같은 이름은 그 군이 보인 뒤에 붙인다.
- 군이 20명 미만이면 퍼센트 대신 그 사람들의 카드를 보여 준다.
- 화면에 결핍, 부족 판정, 복용 권유를 쓰지 않는다.

## 5. 이번 버전에서 만드는 것

1. 로그인하지 않아도 공개 스택과 제품 방을 볼 수 있다.
2. 로그인한 사람이 제품을 검색해 체크한다. 1회 분량 배수와 먹는 시간을 정한다.
3. 목록에 없는 제품은 이름과 함량을 직접 추가한다.
4. 체크한 제품이 모이면 그 사람의 공개 스택 카드가 된다.
5. 제품 방에 그 제품을 체크한 사람들의 카드가 나온다.
6. 카드에 200자 안의 질문을 달고, 본인 질문은 지울 수 있다.
7. 카드 안에 오늘 함량 합계를 작게 보여 준다.
8. 성분이 3개 이상 겹치는 군을 계산한다. 20명 미만이면 카드 목록, 20명 이상이면 성분 차이를 퍼센트로 보여 준다.

## 6. 이번 버전에서 만들지 않는 것

- 식단 기록, 칼로리 목표, 검진 연동, 웨어러블
- 복용 알림, 재고, 사진 인식, 바코드
- 별점, 가격 비교, 구매 링크, 제품 추천
- 조합 점수, 상위 퍼센트, "부족합니다", "드세요"
- 자유 게시판, 댓글의 댓글, 좋아요
- 이름 붙인 고민 카테고리 관리 화면
- 고민을 먼저 고르는 가입 단계

## 7. 쓰는 흐름

### 7.1 처음 온 사람

1. 홈에서 최근 공개 스택을 본다.
2. 제품 이름을 눌러 그 제품 방으로 들어간다.
3. 방 안에서 다른 사람의 카드를 연다.

계정이 없어도 여기까지 된다.

### 7.2 참여

1. 메일로 로그인한다.
2. 표시 이름을 정한다.
3. 제품을 검색해 체크한다. 배수는 기본 1, 시간은 아침·점심·저녁·자기 전 중 하나.
4. 체크하는 순간 그 제품 방에 내 카드가 나타난다.
5. 다른 카드에 질문을 남긴다.

### 7.3 목록에 없을 때

1. 검색 결과가 없으면 제품을 직접 추가한다.
2. 제품명만 있어도 방이 생긴다.
3. 1회 분량과 성분 함량을 적으면 그날부터 합계와 군 계산에 들어간다.
4. 함량이 없는 제품은 제품 방에는 나오고, 성분 군에는 나오지 않는다.

## 8. 화면

첫 화면은 다른 사람의 스택이다. 내 함량 합계는 내 카드 안의 작은 영역이다.

| 화면 | 경로 | 보이는 것 |
| --- | --- | --- |
| 홈 | `/` | 최근 공개 스택 20장. 내가 체크한 제품이 있으면 그 제품 방으로 가는 입구를 위에 둔다. |
| 제품 방 | `/products/:id` | 제품명, 제조사, 1회 분량. 이 제품을 체크한 공개 스택. |
| 스택 카드 | `/stacks/:userId` | 그 사람이 체크한 제품, 배수, 시간. 오늘 함량 합계. 질문 목록과 입력칸. |
| 내 스택 | `/me` | 검색, 체크, 배수, 시간, 체크 해제, 직접 추가. 카드 공개 스위치. |
| 겹치는 군 | `/me/cohort` | 아래 9절 규칙. 내 스택이 있어야 열린다. |

빈 홈은 "아직 공개된 스택이 없다"와 내 스택을 만드는 버튼만 둔다. 안내 문구로 채우지 않는다.

## 9. 군과 문장

군은 저장하지 않고 조회할 때마다 계산한다.

- 내 성분 키는, 지금 체크 중이고 함량이 있는 제품에서 나온 영양성분 이름이다. 용량이 달라도 같은 키면 겹친 것이다.
- 다른 공개 스택과 키가 3개 이상 같으면 그 사람이 군에 들어온다. 본인은 군 수에서 뺀다.
- 군이 20명 미만이면 그 카드만 보여 주고 퍼센트는 숨긴다.
- 군이 20명 이상이면 두 목록을 보여 준다.
  - 군에는 있고 내 스택에는 없는 성분. 그 성분을 가진 사람 수 / 군 인원.
  - 내 스택에만 있는 성분. 군에서 가진 사람이 0명인 키.

문장 예:

> 이 군 142명 중 68%가 마그네슘을 자기 전에 먹는다. 네 스택에는 없다.

시간은 그 성분이 들어 있는 제품의 시간 중, 군에서 가장 많은 시간을 쓴다. 동률이면 시간을 빼기만 한다.

금지 문장: 부족하다, 결핍이다, 드세요, 추천합니다, 위험합니다.

## 10. 데이터

Postgres 한 대.

### users

| 컬럼 | 설명 |
| --- | --- |
| id | uuid |
| email | 로그인 키. unique |
| display_name | 카드에 보이는 이름 |
| stack_public | 기본 true. false면 홈, 제품 방, 군에서 빠진다. 본인 `/me`에는 남는다. |
| role | `member` 또는 `admin`. 첫 계정만 admin. |

### products

| 컬럼 | 설명 |
| --- | --- |
| id | uuid |
| registration_no | 품목제조신고번호. 공공 데이터 키. 직접 추가 제품은 null. unique where not null |
| name | 제품명 |
| manufacturer | 제조사. 없어도 됨 |
| serving_text | "1회 2캡슐" 같은 라벨 문장 |
| source | `public` 또는 `user` |
| created_by | 직접 추가한 사람. 공공 제품은 null |

같은 사람당 체크는 제품당 하나다. 아침과 저녁에 나눠 먹는 경우는 이번 버전의 메모로만 적는다. 행을 두 개 만들지 않는다.

### product_nutrients

| 컬럼 | 설명 |
| --- | --- |
| id | uuid |
| product_id | |
| nutrient_key | 비교에 쓰는 정규화 키. 공백 제거, 소문자 |
| display_name | 화면에 쓰는 이름. 예: 마그네슘 |
| amount | 1회 분량 기준 숫자 |
| unit | mg, μg, kcal, CFU 등 |
| origin | `public` 또는 `user` |
| locked | true면 월간 가져오기가 이 행을 바꾸지 않는다 |

열량은 `nutrient_key = energy`, unit `kcal`인 행이다. 라벨에 있을 때만 있다. 식단 목표로 쓰지 않는다.

### stack_items

| 컬럼 | 설명 |
| --- | --- |
| id | uuid |
| user_id | |
| product_id | |
| servings | 0보다 큰 소수. 기본 1. 하루 양 = 1회 분량 함량 × servings |
| time_slot | `morning` `noon` `evening` `bedtime` |
| unique | (user_id, product_id) |

체크를 해제하면 행을 지운다. 제품 방에서 바로 빠진다.

### questions

| 컬럼 | 설명 |
| --- | --- |
| id | uuid |
| stack_user_id | 질문이 달린 카드의 주인 |
| author_id | |
| body | 1자 이상 200자 이하 |
| created_at | |

본인과 admin만 지울 수 있다. 답글은 없다.

## 11. 카탈로그

원천은 공공데이터포털의 전국건강기능식품영양성분정보표준데이터다. 한 행이 제품 하나이고, 열량·비타민·미네랄이 컬럼으로 있다.

가져오기:

1. 파일을 읽어 품목제조신고번호가 있는 행만 남긴다.
2. 번호가 없으면 `products`에 넣고 `source = public`으로 둔다.
3. 번호가 있으면 이름, 제조사, 1회 분량 문장을 갱신한다.
4. 알려진 영양성분 컬럼을 `product_nutrients`로 펼친다. 값이 비어 있거나 0이면 행을 만들지 않는다.
5. `locked = true`이거나 `origin = user`인 행은 건너뛴다.
6. 직접 추가 제품은 `registration_no`가 없어서 이 작업이 건드리지 않는다.

이번 버전에서 펼치는 컬럼은 열량, 단백질, 지방, 탄수화물, 나트륨, 칼슘, 철, 비타민 C, 비타민 D, 그리고 파일에 숫자로 들어 있는 나머지 비타민·미네랄이다.

루테인, EPA, DHA, 홍삼 지표성분, 유산균 수는 이 파일의 배합비 밖에 있는 경우가 많다. 그 함량은 제품 화면에서 사람이 행을 추가한다. 추가하는 순간 그 행은 `origin = user`, `locked = true`다.

실행은 `pnpm import:catalog --file <csv>`다. 스케줄러는 만들지 않는다. 한 달에 한 번 이 명령을 다시 실행한다.

성분 키는 표시 이름을 소문자로 만들고 공백을 뺀 값이다. 같은 성분의 다른 표기는 작은 별칭 표로 맞춘다.

| 들어오는 이름 | nutrient_key |
| --- | --- |
| 비타민 C, vitamin c, 아스코르브산 | vitamin-c |
| 비타민 D, vitamin d, 비타민 D3 | vitamin-d |
| 마그네슘, magnesium | magnesium |
| 칼슘, calcium | calcium |
| 철, iron | iron |
| 열량, energy, 에너지 | energy |

별칭 표에 없는 이름은 소문자·공백 제거 키 그대로 쓴다. 사람이 추가한 "루테인"과 공공 데이터의 "루테인"은 같은 키가 된다.

## 12. 하루 함량

카드의 합계는 체크 중인 제품만 본다.

```
하루 양(키) = Σ (그 키의 1회 분량 amount × stack_item.servings)
```

단위가 다른 같은 키는 합치지 않고 단위별로 줄을 나눈다. μg을 mg로 바꾸는 표는 이번 버전에 없다.

## 13. 구현

한 웹 앱으로 만든다. 앱과 배치를 나누지 않는다.

| 층 | 선택 | 이유 |
| --- | --- | --- |
| 앱 | Next.js, TypeScript, App Router | 화면과 서버 조회를 한 저장소에 둔다. |
| DB | PostgreSQL | 제품, 성분, 체크, 질문이 서로 참조한다. |
| 조회 | Drizzle | 스키마가 이 문서의 표와 1:1로 보인다. |
| 로그인 | Auth.js 이메일 매직 링크 | 커뮤니티에 필요한 것은 안정된 계정이다. 비밀번호 저장과 카카오 심사는 뒤로 미룬다. |
| 가져오기 | `tsx` 스크립트 하나 | CSV를 위 11절 규칙으로 upsert 한다. |

디렉터리:

```
src/app/page.tsx                      홈
src/app/products/[id]/page.tsx        제품 방
src/app/stacks/[userId]/page.tsx      스택 카드
src/app/me/page.tsx                   내 스택
src/app/me/cohort/page.tsx            겹치는 군
src/db/schema.ts                      10절 표
src/server/stacks.ts                  체크, 공개 카드, 합계
src/server/cohort.ts                  9절 계산
src/server/catalog/import.ts          11절 가져오기
src/server/catalog/aliases.ts         별칭 표
src/server/questions.ts               질문 작성, 삭제
```

공개 조회는 서버 컴포넌트가 Postgres를 직접 읽는다. 체크, 질문, 직접 추가는 서버 액션이다. 별도 API 서버는 없다.

로컬에서 먼저 연다. 친구에게 보여줄 때 같은 앱과 Postgres를 한 주소로 연다. 호스트는 그 시점에 정한다.

## 14. 만드는 순서

각 단계가 끝나면 그 단계만으로 확인한다. 다음 단계의 화면을 미리 만들지 않는다.

### 1단계. 빈 카드가 공개된다

스키마, 매직 링크 로그인, 표시 이름, 제품 검색, 체크, 해제, 직접 추가, 내 카드, 홈의 최근 카드, 제품 방.

확인:

- 제품을 체크하면 홈과 그 제품 방에 내 카드가 나온다.
- `stack_public = false`면 두 곳에서 사라진다.
- 같은 제품을 두 번 체크해도 행은 하나다.
- 함량 없는 직접 추가 제품도 제품 방이 생긴다.

### 2단계. 카드에 질문이 달린다

확인:

- 로그인하지 않으면 질문은 보이지 않고 입력칸은 로그인으로 보낸다. 질문 목록은 로그인 없이도 읽힌다.
- 201자는 거절된다.
- 본인 질문과 admin 질문 삭제만 된다.

### 3단계. 함량과 군

가져오기 스크립트, 별칭, 카드 안의 하루 합계, `/me/cohort`.

확인:

- 같은 품목제조신고번호를 두 번 가져오면 제품은 하나다.
- `locked` 행의 숫자는 두 번째 가져오기 뒤에도 같다.
- 겹치는 성분이 2개면 군에 들어가지 않는다. 3개면 들어간다.
- 군이 19명이면 퍼센트 문구가 없다. 20명이면 있다.
- 합계 문장에 부족, 결핍, 드세요가 없다.

## 15. 실패할 때 이렇게 동작한다

- 검색어가 비어 있으면 결과를 내려주지 않는다.
- 검색은 제품명과 제조사에 대해 대소문자 무시 부분 일치이고, 20건에서 자른다.
- `servings`가 0 이하이면 저장하지 않는다.
- 비공개 스택의 주소는 본인과 admin만 연다. 다른 사람은 404다.
- 가져오기 파일에 품목제조신고번호가 없는 행은 건너뛰고 건수를 출력한다.
- 질문 본문의 앞뒤 공백은 제거하고, 남은 길이가 0이면 거절한다.
